# Audit 2026-09-10 — Oracle Knowledge Platform

Requested repo `Orackle-Knowledge-Platform.git` does not exist.
Inspected `UthieZz/Oracle-Knowledge-Platform` (current implementation truth).

OKC compiler, importers, analyzers, and KnowledgeObject constructor sites were not edited.

## Verdict

Working beta compiler + exporter + Studio stack. Highest remaining risk is operational (Firestore client coupling, committed output artifacts, dual UI), not a missing compiler rewrite.

## Findings (current repo)

### Weak / broken

- `FirestoreExporter` constructed the GCP client in `__init__`. Any `ExportService` construction required `google.cloud` + credentials even for portable Markdown export. Fixed: lazy `db` property.
- `KnowledgePackage.add_*` appended duplicates; lookups were O(n). Fixed: identity maps + skip-on-duplicate id for conversations, KOs, attachments.
- Entity and attachment Firestore documents omitted lineage. Fixed: publish `provenance`, `message_id`, source/confidence.
- `tests/test_grok_single_file_and_provenance.py` asserted `.id` on a string (`next(...)` already yields `c.id`). Fixed.
- KnowledgeObject.provenance remains an untyped dict. Repair lives in `src/validators/knowledge_object_provenance.py` (not the compiler). Keep it that way.
- `ExportService` still imports `FirestoreExporter` at module load, so `google.cloud` must be installed to import the service. Not changed: would require an exporter registry split.

### Obsolete / redundant (left in place)

- Dual UI: `src/ui` desktop + `studio/` web + `src/studio` Flask bridge. Flask stays until Firestore read path is verified.
- `output/` and `output_split/` committed compiled artifacts. Packaging, not compiler. Do not treat as canonical knowledge.
- Dockerfile exists contrary to locked architecture (“do not introduce Docker to solve Firebase-native beta problems”). Not deleted this pass; flag only.

### Scale / strengthen next (not done)

- Split portable exporters from Firestore so Markdown export does not import GCP.
- Grounded-chat citation check against `KO.evidence` / `provenance.message_ids`.
- Do not add vector DB, Cloud Run, or a second compiler.
- Do not mutate compiler passes to invent semantic types.
