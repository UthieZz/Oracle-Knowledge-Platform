# Audit 2026-09-11 — Oracle Knowledge Platform

Requested repo `Orackle-Knowledge-Platform.git` does not exist.
Audited `UthieZz/Oracle-Knowledge-Platform` @ main.

Constraint honored: OKC compiler, importers, analyzers, and KnowledgeObject constructor were not edited.

## Verdict

Working beta compiler + portable export + Firestore publisher + Studio grounded chat.
Not production-hardened. Knowledge quality still conversation-shaped in many KOs.

## Weak / broken (current repo evidence)

- KO provenance is still an untyped dict on the model. Repair happens after compile in `src/validators/knowledge_object_provenance.py` (added 2026-09-09).
- FirestoreExporter constructed a GCP client in `__init__`, so import/tests required SDK/credentials.
- Entity / attachment Firestore docs omitted lineage fields.
- KO `conversation_id` previously fell back to `object_id`, collapsing identities.
- Grounded chat attached every retrieved hit as a citation whether the model cited it or not.
- `.env` and `__pycache__` exist in git history despite `.gitignore`. `.env` is listed as ignored now; rotate any keys that were ever committed.
- Dual UI (`src/ui`, `src/studio`, `studio/`) and Flask `api_server` remain. Leave until Firestore read path is verified.
- Committed `output/` compiled artifacts inflate the repo.

## Implemented this pass

- Lazy Firestore client + optional injected client; SDK import optional.
- Stop publishing KO `conversation_id = object_id` when provenance has no conversation.
- Entity and attachment documents now include provenance (`conversation_id`, `message_id`, source / attachment_id).
- `src/validators/citation_verifier.py` + tests.
- Studio `ChatService.verifyCitations` keeps only `[Source N]` actually used in the answer.

## Not done (by design)

- Did not change KnowledgeObject dataclass, KnowledgePackage mutability, importers, or compiler passes.
- Did not delete Flask or dual UI.
- Did not add vector DB / Docker / second compiler.
- Did not rewrite taxonomy or invent a graph database.
