# Audit 2026-09-12 — Oracle Knowledge Platform

Constraint: OKC compiler, importers, analyzers, KnowledgeObject dataclass, KnowledgePackage internals were not edited.

## Verdict

Beta compiler + portable export + Firestore publisher + Studio is real.
Knowledge quality is still conversation-archive shaped in unified output titles.
Provenance exists as an untyped dict plus a post-compile repair pass. That is the correct boundary given the no-OKC-edit constraint.

## Facts from repo

- Canonical KO fields: id, title, content, source_platform, source_file, timestamps, provenance dict, evidence list.
- Repair: `src/validators/knowledge_object_provenance.py` fills platform / file / conversation_id / message_ids / attachment_ids / object_type.
- FirestoreExporter already publishes provenance and evidence and no longer invents conversation_id = object_id.
- Dual UI + Flask still present. Leave until Firestore read path is the only Studio path.
- Committed `output/` and `uploads/` inflate the repo. `.env` was a comment stub; removed from tree this pass.
- Studio `getKnowledgeObjects` defaulted missing type to `conversation`. That is a consumer contract bug, not a compiler bug.
